# `configs/v0.3-exp001.json` — field reference

This file documents every field of the EXP-001 config and says whether it is **frozen** (must
equal v0.2.0), **changed** (the one experimental variable), **identity** (run metadata that has
to differ so the two runs never collide), or **record** (a provenance value that is written down,
not used to train). `scripts/validate_exp001.py` enforces the frozen and identity rules and fails
on any mismatch instead of correcting it.

The v0.2.0 reference values come from `configs/v0.2.json` plus the `ShnuConfig` defaults in
`src/shnu_llm/config.py`. They match the configuration stored in the v0.2.0 checkpoint and are
summarised in `docs/EVALUATION_v0.2.0.md`.

## `config_schema_version`

Record. The schema version of this file, currently 1.

## `provenance`

Record, checked by the validator. It sorts every input into one of four lists.

| Field | Meaning |
|---|---|
| `frozen_from_v0_2` | Values that must equal v0.2.0: architecture, tokenizer, the WikiText train and validation streams, training and evaluation. |
| `new_in_exp001` | Values introduced by this experiment: the FineWeb-Edu source, its preprocessing (including `min_chars`), the mix, the FineWeb-Edu held-out set, `shnu_config.version` and the output identity. |
| `unresolved_before_training` | Pins that are still `null`. Every `null` pin must be listed here, and no WikiText value may be. |
| `unknown_historical` | v0.2 facts that no artifact proves. At present this is only the `min_chars` used in the v0.2 preparation. |

Components and validation sets also carry a `provenance_class` (`frozen_from_v0_2` or `new_in_exp001`).

## `output` (identity)

| Field | Value | Why |
|---|---|---|
| `run_name` | `shnu_v0.3_exp001` | Must not be `shnu_v0.2`. |
| `out_dir` | `runs/shnu_v0.3_exp001` | Must equal `shnu_config.out_dir` and must not be a v0.2.0 run directory. |
| `must_not_equal` | known v0.2.0 run directories | Added to the validator's own hard-coded list, never subtracted from it. |

**Run identity.** `scripts/train_exp001.py` passes `run_name` to `resume_training`, which passes it
to `TrainingStatus.for_run`. EXP-001's status file is therefore
`<out_dir>/runs/shnu_v0.3_exp001/training_status.json`, and its `run_name` field is
`shnu_v0.3_exp001`. Both `resume_training` and `TrainingStatus` still default to `shnu_v0.2`, so
v0.2 behaviour is unchanged.

## `shnu_config` (frozen, except the two identity fields)

This is the exact block passed to `ShnuConfig(**...)`. `scripts/train_exp001.py` loads it
(`build_shnu_config`), sets only `out_dir` to the run directory given on the command line, and calls
the existing `resume_training`. The v0.2 scripts (`scripts/resume.py --config`, `scripts/train.py`)
still read flat JSON files such as `configs/v0.2.json`. They are not meant to be given
`configs/v0.3-exp001.json`, and would reject it.

- **Every field is listed.** Each `ShnuConfig` field appears explicitly, so nothing depends on changeable defaults, and the validator rejects unknown fields.
- **Only identity fields may differ.** Compared with the v0.2.0 effective config, only `version` (`v0.3`) and `out_dir` (`runs/shnu_v0.3_exp001`) may differ. Any other difference fails validation.
